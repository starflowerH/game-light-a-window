# 3D / CA / 美工美术管线

> 结论：不做“纯网页绘图”。  
> 最终画面 = **CA 概念美术定调 + Blender 低模与烘焙出资产 + Three.js 实时交互与光效**。  
> 网页不是画布替代品，而是“可玩引擎层”。

---

## 1. 为什么必须升级

纯 CSS/Canvas 画窗户的问题：

- 能做交互，但材质、光照、空间感上限低
- 容易像网页组件，不像“游戏作品”
- 窗光、树影、雨雾缺少真实层次
- 封面、明信片、场景难以统一到同一美术语言
- 评审第一眼会把它当“前端页面”，不是“游戏”

升级后：

- Blender 负责空间、材质、灯光、烘焙
- CA 负责气氛、构图、角色/道具/明信片美术
- Three.js 负责实时交互、天气、粒子、窗户状态
- 三者组合，既有 3D 质感，又能 30MB 内跑起来

---

## 2. 三层美术架构

```text
Layer A：CA 概念美术
  用途：定风格、定色彩、定构图、封面、明信片、故事窗插画
  产出：概念图、色板、构图稿、明信片原画

        ↓ 作为参考与贴图来源

Layer B：Blender 资产与烘焙
  用途：宿舍楼、窗户、树、路灯、地形、材质、灯光
  产出：GLB、烘焙贴图、AO、Lightmap、预渲染大图

        ↓ 导出与压缩

Layer C：Three.js 实时层
  用途：窗户点亮、连击、雨雾、粒子、镜头、交互
  产出：可玩游戏
```

## 3. CA 概念美术

### 3.1 定义

CA = Concept Art，概念美术。  
不是最终游戏资产，而是用来定调、对齐、生产参考的美术。

### 3.2 需要产出

| 资产 | 数量 | 用途 |
|---|---|---|
| 主视觉概念图 | 3 | 雨夜 / 风夜 / 晴夜 |
| 宿舍楼正视图 | 1 | Blender 建模参考 |
| 窗户状态设定 | 1 | 暗/亮/故事/连击 |
| 故事窗小景 | 8–12 | AI 生图 + 人工修 |
| 明信片原画 | 3 | 结算与分享 |
| UI 风格板 | 1 | 按钮、边框、字体、纸张 |
| 色彩脚本 | 3 | 三晚情绪曲线 |

### 3.3 生产方式

1. AI 生成初稿（imagegen）
2. 人工挑选
3. 局部重绘 / 手动修
4. 统一色板与笔触
5. 输出概念图与参考图

### 3.4 CA 审稿标准

- 能一眼看出是校园夜景
- 有明确暖光焦点
- 笔触统一，不像多张 AI 图拼贴
- 不写实、不科幻、不赛博
- 能直接指导 Blender 建模
- 能直接裁成明信片

## 4. Blender 资产管线

### 4.1 Blender 负责什么

- 宿舍楼体块
- 24 扇独立窗户
- 屋顶、窗框、墙裙、雨棚
- 树、灌木、路灯、长椅、自行车
- 地面、台阶、小路
- 材质：砖墙、玻璃、木材、金属
- 灯光：月光、窗内暖光、路灯
- 烘焙：AO、Lightmap
- 预渲染：封面、明信片、故事窗背景

### 4.2 不做什么

- 不做角色骨骼动画
- 不做复杂角色绑定
- 不做开放世界
- 不做高模写实
- 不做实时全局光照

### 4.3 场景规格

| 项目 | 目标 |
|---|---|
| 楼体面数 | 3k–8k tris |
| 每扇窗 | 独立 mesh，命名 window_01…window_24 |
| 树 | 2–3 种，低模 + 贴图 |
| 场景总面数 | < 60k tris |
| 材质数 | < 12 |
| 纹理 | 2K atlas 1–2 张 |
| 灯光 | 1 个主光 + 1 个补光 + 窗户自发光 |
| 烘焙 | AO + Lightmap（Eevee/Cycles） |

### 4.4 窗户规范（关键）

每扇窗必须独立，方便 Three.js 单独控制：

- 命名：`window_01` 到 `window_24`
- 自定义属性：`window_id = 01`
- 材质：玻璃 + 窗框分开
- 玻璃使用自发光材质
- 暗态自发光强度 0
- 亮态自发光强度 3–6
- 暖色 `#F2C46D` 到 `#FFE9B0`
- 不要合并成一整块，否则无法交互

### 4.5 Blender Python 自动化

用脚本生成：

- 4×6 窗户阵列
- 窗框
- 楼层线
- 屋顶
- 简易树与路灯
- 导出 GLB
- 批量重命名与自定义属性

这样可以不依赖手工建模完成第一版。

## 5. 烘焙与渲染

### 5.1 两套渲染用途

| 用途 | 引擎 | 说明 |
|---|---|---|
| 实时游戏资产 | Eevee 预览 + 烘焙 | 轻量、快 |
| 封面/明信片 | Cycles | 高质量、可慢 |

### 5.2 烘焙内容

- AO
- Lightmap
- 窗框细节
- 墙面笔触
- 地面污渍

### 5.3 预渲染内容

- 封面主图 1920×1080
- 三晚明信片 1080×1440
- 故事窗小景 512×512
- 评审速览图

### 5.4 烘焙原则

- 不在网页里做实时全局光照
- 不在网页里做复杂阴影
- 窗光用自发光 + Sprite 光晕
- 天气用 Three.js 粒子
- 保持 60fps 桌面 / 30fps 移动

---

## 6. Three.js 实时层

### 6.1 加载

- GLB 通过 `GLTFLoader` 加载
- 纹理使用 KTX2 / WebP
- 使用 Draco 或 Meshopt 压缩
- 首屏先显示预渲染背景，再替换为实时场景

### 6.2 窗户控制

```ts
const windowMesh = scene.getObjectByName('window_07')
const material = windowMesh.material as THREE.MeshStandardMaterial
material.emissive.set('#F2C46D')
material.emissiveIntensity = 3.5
```

### 6.3 天气

| 天气 | Three.js 实现 |
|---|---|
| clear | 星星 Sprite + 月光 |
| light_rain | InstancedMesh 雨线 + 窗面水痕贴图 |
| fog | Scene.fog + 半透明雾层 |
| wind | 树影 UV 偏移 + 粒子斜飞 |

### 6.4 性能

- 窗户只改材质参数，不重建 mesh
- 粒子上限 500
- 光晕用 Sprite，不用后处理泛光做全屏
- 移动端降低粒子数与阴影
- 页面隐藏时暂停渲染

## 10. 美术生产流程

```text
1. 色板与情绪板
2. AI 生成 3 张主视觉概念图
3. 人工挑 1 张定调
4. 用 CA 图指导 Blender 体块
5. Blender 自动生成窗户与楼体
6. 材质与灯光 lookdev
7. 烘焙 AO / Lightmap
8. 导出 GLB + 纹理
9. Three.js 集成
10. 窗户点亮 / 天气 / 粒子
11. 预渲染明信片与封面
12. 统一 UI 与排版
13. 性能与视觉验收
```

## 11. 验收标准

### 视觉

- 有明确 3D 空间感
- 窗户光有真实自发光层次
- 墙面/屋顶有笔触纹理
- 雨雾不是纯 CSS 贴图
- 截图能直接当封面

### 技术

- GLB < 3MB
- 总包 < 12MB
- 60fps 桌面
- 移动端 30fps
- 无 WebGL 报错
- 窗户可独立控制

### 工程

- Blender 源文件不入提交包
- 导出资产与源文件分离
- 每个资产有来源与许可
- 所有 AI 图有人工审核记录
