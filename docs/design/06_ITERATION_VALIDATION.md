# 迭代与验证计划

> 原则：先纸面验证，再灰盒，再美术，再 AI，最后联调。  
> 每一轮必须有明确的“通过/修改/砍掉”标准。

---

## 1. 轮次总览

| 轮次 | 名称 | 目标 | 交付物 |
|---|---|---|---|
| R0 | 纸面验证 | 验证核心循环是否好玩 | 纸面原型 + 测试记录 |
| R1 | 灰盒可玩 | 验证点击/连击/进度 | 可运行灰盒 |
| R2 | AI 接入 | 验证 DeepSeek 生成与 fallback | AI 正常/失败均能玩 |
| R3 | 美术替换 | 验证卡通油画风格 | 主场景 + 明信片 |
| R4 | 内容与音效 | 验证故事窗与声音 | 内容包 + 音效 |
| R5 | 工程与部署 | 验证性能、移动端、上线 | 可公开访问版本 |
| R6 | 评审演练 | 验证 30 秒可看懂、5 分钟可玩完 | 演示视频 + 速览 |

---

## 2. R0 纸面验证

### 目标

在不写代码的情况下验证：

- 核心动作是否易懂
- 连击是否有爽感
- 三晚是否有变化
- 故事窗是否打断节奏

### 方法

- 用纸画 24 个窗格
- 用硬币/便签代表发光窗
- 找 3 个人各玩 5 分钟
- 记录：
  - 第一次点击时间
  - 是否理解规则
  - 是否觉得无聊
  - 是否想再玩
  - 哪里最爽
  - 哪里最烦

### 通过标准

- 3/3 在 15 秒内理解
- 2/3 说“想再玩”
- 0/3 说“有压力”
- 至少 1 人主动提到“连击很爽”

### 修改方向

- 如果太简单：增加发光窗数量或缩短持续时间
- 如果太乱：降低同时发光窗上限
- 如果故事窗烦：减少故事窗频率或允许一键跳过
- 如果没感觉：加强光链和声音

## 3. R1 灰盒可玩

### 目标

验证真实输入下的手感。

### 范围

- 24 扇窗
- 点击点亮
- 连击
- 温暖值
- 单晚 75 秒
- 无 AI
- 无美术
- 无音效（可先用简单 beep）

### 通过标准

- 30 秒内可开始
- 60 秒内出现第一次连击
- 无输入延迟
- 无控制台错误
- 3 人测试中 2 人想再玩

### 修改方向

- 点击热区太小 → 扩大 12px
- 发光窗太难找 → 提高对比度
- 连击断得太快 → 延长 combo window
- 节奏太慢 → 缩短发光时长

---

## 4. R2 AI 接入

### 目标

验证：

- Key 校验
- 三晚生成
- JSON 校验
- 超时
- 非法输出
- fallback

### 测试用例

| 用例 | 输入 | 预期 |
|---|---|---|
| 正常 Key | 有效 Key | 生成三晚 |
| 无效 Key | `sk-invalid` | 提示无效，可离线 |
| 无网络 | 断网 | 自动 fallback |
| 超时 | 模拟 30s | 自动 fallback |
| 非法 JSON | mock | 重试一次，再 fallback |
| 禁用词 | mock | 内容过滤 |
| 超长文案 | mock | 截断 |
| XSS 字符串 | mock | 转义 |

### 通过标准

- 所有失败路径都能继续玩
- Key 不出现在控制台
- Key 不写入 storage
- 不阻塞游戏
- fallback 内容也好看

## 5. R3 美术替换

### 目标

验证卡通油画风格。

### 范围

- 主场景
- 24 扇窗
- 3 种天气
- 故事窗小景
- 明信片
- UI

### 通过标准

- 截图可直接作为封面
- 一眼看出可点窗户
- 暖光与夜蓝对比清晰
- 没有写实/科幻/赛博元素
- 移动端不糊
- 3 人中有 2 人说“好看”

### 修改方向

- 太暗 → 提高窗光亮度
- 太花 → 减少细节
- 太像网页 → 增加画布纹理和手绘边框
- 太像 AI 图 → 统一笔触和色彩

---

## 6. R4 内容与音效

### 目标

验证故事窗和声音是否增强体验。

### 范围

- 24 条故事
- 10 个物件
- 点击音
- 连击音
- 环境音
- 明信片文案

### 通过标准

- 故事能在 3 秒内读完
- 没有说教
- 声音不刺耳
- 可关闭
- 3 人中有 2 人说“声音舒服”
- 3 人中有 0 人说“像在教我”

### 修改方向

- 故事太长 → 截短
- 故事太丧 → 调整语气
- 音效太尖 → 降低高频
- 音乐太吵 → 降低音量或换环境音

---

## 7. R5 工程与部署

### 目标

验证可上线。

### 检查项

- 首屏 < 3s
- 总包 < 12MB
- 无控制台错误
- 无 404
- 移动端不崩
- 键盘可操作
- 声音可关闭
- 减少动画可开启
- 排行榜可关闭
- Key 不落地
- API 健康检查正常

### 通过标准

- Lighthouse Performance ≥ 80
- Accessibility ≥ 90
- 无 P0/P1 缺陷
- 3 个不同浏览器通过

## 8. R6 评审演练

### 目标

验证评审现场能在 30 秒内看懂。

### 演练脚本

1. 0–10 秒：打开页面，看到夜景和发光窗
2. 10–30 秒：点击第一扇窗，看到光、听到声
3. 30–60 秒：连击，光链扩散
4. 60–90 秒：故事窗出现
5. 90–120 秒：明信片生成

### 通过标准

- 不看说明也能玩
- 30 秒内出现第一次“哦”
- 90 秒内出现第一张明信片
- 评审能一句话说出玩法

---

## 9. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 无法开始/无法继续/Key 泄露 | 立即修复 |
| P1 | 核心玩法不可用/严重卡顿 | 发布前修复 |
| P2 | 视觉错位/文案错误 | 发布前修复 |
| P3 | 小动画/小音效问题 | 可延后 |

---

## 10. 迭代修改原则

1. 每轮只改一个核心变量
2. 每次修改记录原因与结果
3. 不因“看起来更高级”增加复杂度
4. 不因“别人有”增加功能
5. 优先修“第一次体验”
6. 优先修“30 秒内的问题”
7. 优先修“声音和反馈”
8. 砍功能优先于加功能

## 12. 数值验证表（设计阶段）

### 12.1 单晚点击频率假设

| 玩家类型 | 点击频率 | 75 秒点击数 | 预估单晚温暖值 |
|---|---|---|---|
| 慢 | 0.8 次/秒 | 60 | 约 150 |
| 正常 | 1.0 次/秒 | 75 | 约 190 |
| 快 | 1.2 次/秒 | 90 | 约 230 |
| 很慢/挂机 | 0.3 次/秒 | 22 | 约 50 |

### 12.2 结论

- 100 作为“全楼亮起”阈值是合理的，正常玩家约 45–60 秒触发。
- 单晚温暖值可能超过 100，因此 UI 进度条以 100 为满值，额外部分显示为“超额光”。
- 三晚总温暖值用于结算，不用于判断玩家情绪。
- 挂机玩家也能正常结算，只是全楼不亮，不惩罚。

### 12.3 故事窗频率验证

| 夜晚 | 时长 | 故事窗次数 | 平均间隔 | 结论 |
|---|---|---|---|---|
| 1 | 75s | 1 | 约 40s | 不打断学习 |
| 2 | 75s | 2 | 约 25s | 有一点呼吸 |
| 3 | 75s | 2 | 约 25s | 收束前留白 |

> 若 R1 测试发现故事窗打断节奏，优先减少第 2、3 晚的次数，而不是删掉功能。

## 13. 设计决策日志

| 决定 | 原因 | 替代方案 | 状态 |
|---|---|---|---|
| 点击发光窗户作为唯一核心动作 | 易上手、快反馈、移动端友好 | 拖拽/长按/划线 | 采纳 |
| 24 扇窗 | 视觉完整、够玩但不复杂 | 12/36/48 | 采纳 |
| 三晚 75 秒 | 总时长约 5 分钟 | 单晚 3 分钟 | 采纳 |
| 无失败惩罚 | 解压定位 | 倒计时扣分 | 采纳 |
| AI 开场生成三晚 | 不打断节奏 | 实时生成 | 采纳 |
| 2.5D 分层 | 视觉强、成本低 | 全 3D | 采纳 |
| 卡通油画 | 温暖、差异化 | 低多边形/像素 | 采纳 |
| 排行榜默认折叠 | 避免压力 | 默认展开 | 采纳 |
| 不做 AI 聊天 | 避免同质化和说教 | 树洞聊天 | 采纳 |
| 不做心理测评 | 避免诊断和伦理风险 | 情绪测试 | 采纳 |
